# Атлас AgPM — правила для агентов

## Сначала прочитать: действующая эксплуатация

Перед изменениями конвейера, хранения или деплоя прочитай
[передачу изменений от 02.11.2026](docs/operations/claude-handoff-2026-11-02.md)
и [канонический контракт хранения](docs/operations/storage.md).
Они описывают внедрённую схему, а не план переноса. Старые отчёты этапов — история.

Отдельное приложение: еженедельный «Атлас агентного управления проектами» по
материалам AgPM Radar. Задание — `docs/spec/Задание_на_разработку_Атлас_v2.md`,
правила атласа — `Правила_атласа.md` (единственное место, где они записаны),
итоги разведки и решения заказчика — `docs/Записка_разведки_v1.md`.

## Что нельзя менять

- **Номера материалов.** № 1–797 из октябрьского атласа сохраняются навсегда
  (№ 169, 242 и 291 пропущены и не выдаются). Новые номера начинаются с **№ 798**
  (решение заказчика 01.11.2026; в задании ошибочно «с 795»). Номер не
  переиспользуется никогда.
- **Ключи пунктов и разделов** (`B1_drafts`, `practice`…) — часть постоянных адресов.
- **Ручную разметку 2026-10-09.** Автоматика её не удаляет, не переоценивает и не
  «исправляет» типографикой: перенос сверяется с эталоном побайтно.

## Откуда данные

Только API радара V2 (`https://radar.agpm.space/api/issues…`). Старый конвейер
радара, его Markdown-выпуски и раздел «Разбор AI Agents Directory» не
используются — решение заказчика 01.11.2026. Радар из этого репозитория не
меняется.

## Оценки на эталоне нет

Заказчик снял прогон классификатора по 794 материалам эталона (01.11.2026,
`docs/Записка_разведки_v1.md`, раздел 9): нужна только понедельная дельта к
версии 2026-10-09. Качество держат проверка редактором и предохранитель
«резкие изменения». Не предлагать оценку в пять приёмов снова.

## Правило сигнала

Учитываемая связь: роль «внедрение с именем», «независимый обзор» или
«опровержение», оценка «подтверждает» или «опровергает», материал сверен с
источником, есть дословная цитата. Сигнал по учитываемым связям: только
подтверждения — «Подтвердилось», только опровержения — «Не подтвердилось», нет
учитываемых — «Заявлено», есть и те и другие — конфликт, сигнал прежний. На
эталоне правило даёт 26 из 26 при одном исключении: № 117 в `B1_drafts` не
учитывается. Подробно — `Правила_атласа.md`, код — `atlas/rules.py`.

## Язык текстов

Русский, ё, «ёлочки» и „лапки“; без «важный», «ключевой», «уникальный», без
«это не X, а Y», без начала предложения с «Вот», «Это», «Здесь»; числа по
русским правилам.

## Проверки

```
bash scripts/verify.sh
```

Гейт смотрят по коду возврата. `uv` — `/root/.local/bin/uv`, зависимости —
`uv sync`. Тестовые базы называются только `atlas_test_*`: фикстура откажется
работать с другим именем.

## Где что работает

- **Сайт и кабинет** — Local Ru: `/srv/atlas.agpm.space` (current → releases/<версия>),
  `atlas-editor.service`, база `atlas` в PostgreSQL 17. Caddy — `/etc/caddy/atlas.agpm.space.caddy`.
- **Конвейер с моделью** — управляющий сервер `/data/atlas`, crontab root `0 6 * * 1`
  (пн 09:00 МСК) запускает `atlas-weekly.service`, база — через туннель (`atlas-tunnel@`, порт 55432). Локальной базы
  `atlas` здесь нет намеренно: старая копия переименована, команда без туннеля падает.
- Ключ `atlas_publish` умеет только `preview`, `publish` (`deploy/remote.sh`).

## Чему здесь научились

- **После выкладки кода сайта пересобирать папки всех версий** (`atlas.cli rebuild-site`):
  папка версии неизменяема и сама новый код не получит.
- **CSP запрещает встроенные обработчики** (`onclick`, `onchange`): поведение — только
  файлами (`site/assets/cabinet.js`); тест это стережёт.
- **Лишняя «}» в стилях молча выбрасывает следующее правило** — тест парности скобок.
- **`caddy validate` от root** создаёт файлы журналов с владельцем root, и перезагрузка
  Caddy падает. Запускать от пользователя caddy.
- **`pkill -f <шаблон>` убивает и собственную оболочку**, если шаблон есть в тексте
  команды. Останавливать процесс по номеру (`ss -ltnp` → pid).
- Доступность (axe-core) — блокирующая проверка недельного прогона; прежде чем менять
  цвета или разметку, прогнать `tools/a11y_check.cjs`.

## Как работаем

- Задание идёт этапами 0–4. После каждого этапа — остановка и подтверждение
  заказчика.
- Заказчик решает по одному вопросу за раз: описание простыми словами,
  варианты, рекомендуемый первым.
- Сообщения коммитов писать через файл (`git commit -F`), не heredoc'ом в
  кавычках с обратными апострофами.

## Хранение Atlas — 02.11.2026

Конвейер и модель остаются на srv2; root cron запускает atlas-weekly.service.
Рабочий кэш/журналы/дампы — только на Local Ru через ограниченный SSH RPC.
Не возвращать запись в локальный var и старый pg_dump через туннель.
Канонические пути, сроки, проверки и откат: docs/operations/storage.md.
Инструкция дежурного обновлена; исторические отчёты не являются источником рабочих путей.
