### Что из этого следует для атласа

Шаги 1–3 недельного цикла (забор, сверка, классификация) требуют модели
`gpt-6.1-sol`, свободного выхода в сеть и браузера. Всё это есть только на
управляющем сервере. На Local Ru `gpt-6.1-sol` запрещена правилом P9, а выход в
сеть закрыт ADR-0005. Конвейер радара по той же причине работает на управляющем
сервере.

Предлагаемый стек:

| Часть | Где | Чем |
| --- | --- | --- |

| Публичный сайт | Local Ru, `/srv/atlas.agpm.space/` | статические папки версий и атомарное переключение `current`, выкладка по ssh под отдельным ограниченным пользователем — как у газеты и фронта V2 |

Сайт стоит рядом с radar.agpm.space на одном сервере, поэтому домен и Caddy

## 3. Выгрузка радара

Ключ не нужен. Выгрузка — открытый API радара V2:

- `GET https://radar.agpm.space/api/issues?limit=100&cursor=…` — список выпусков, по 100 на страницу, свежие сверху;
- `GET https://radar.agpm.space/api/issues/<ГГГГ-ММ-ДД>` — выпуск целиком, с материалами;
- `GET https://radar.agpm.space/api/materials?period=ГГГГ-ММ&perimeter=&rubric=&cursor=` — материалы с фильтрами.

API отдаёт только материалы, включённые в выпуск: у всех 792 материалов
`verdict = core`. Курсор прогона естественно задаётся датой выпуска.

### Таблица «поле радара → поле атласа»

| — | `outlet` | домен без www: `sourceName` почти всегда канал сбора (Perplexity, Brave, OpenClaw — 621 из 792), а не издание |
| `issueDate` | `radar_dates`, `first_seen`, `month` | у каждого материала в API ровно одна дата (раздел 5, п. 6) |

## 6. Расход на модель

Замеры: `Правила_атласа.md` — 12 тыс. знаков, тексты 27 пунктов — 14 тыс., карточка
радара — около 1,6 тыс., материал эталона — около 450 знаков. Русский текст —
примерно 2,5–3 знака на токен.

| Обращение | Вход | Выход |
| --- | --- | --- |
| Сверка: описание радара и текст источника до 15 тыс. знаков | около 8 тыс. токенов | около 1 тыс. |
| Классификация: правила, пункты атласа, 15–20 ближайших примеров, материал | около 15 тыс. токенов | около 1 тыс. |
| На материал, с повторами (~20 %) | около 28 тыс. | около 2,5 тыс. |

| Прогон | Материалов | Обращений | Токенов |
| --- | --- | --- | --- |
| Недельный | 56 из V2 + около 10 из «Разбора AI Agents Directory», если его берём | около 160 | около 2 млн |
| Догрузка с 10.10 по запуск | 182 из V2 на 01.11 + около 30 из Directory, плюс по 66 за каждую неделю до запуска | около 510 на 01.11 | около 6,5 млн на 01.11 |
| Оценка на эталоне (раз на каждую смену инструкции или модели) | 794 классификации; сверка нужна только 282 связанным материалам | около 1 100 | около 15 млн |

Больше всего уходит на оценку классификатора, а не на недельный прогон. Чтобы
не тратить лимит вслепую, на этапе 2 сначала прогоняю одну пятую эталона
(160 материалов, около 3 млн токенов) и смотрю пороги. Только потом — полный
прогон пятью частями.

## 7. Что нужно от заказчика до этапа 1

По одному вопросу, в порядке важности.

1. **Откуда брать материалы «Разбора AI Agents Directory».**
   - **Из Markdown-выпусков старого конвейера** (рекомендую): переходник читает
     и API V2, и раздел «Разбор» из Markdown. Радар не меняется. Минус: атлас
     привязан к старому конвейеру, а уход от него отложен, но не отменён.
   - **Только из API V2**: проще, но около 22 % потока пропадает.
   - **Доработать V2, чтобы он отдавал этот раздел**: чище всего, но это
     доработка радара, которая в задание не входит.
2. **Новые номера с № 798, а не с № 795**, и что за номера 169, 242, 291.
3. **Где работает кабинет.** Стык между серверами есть в обоих вариантах,
   разница в том, где он проходит.
   - **На управляющем сервере рядом с базой** (рекомендую): Caddy на Local Ru
     проксирует туда `atlas.agpm.space/editor/`. Стык — на каждом действии
     редактора, читателей он не касается. Конвейер, база и кабинет живут
     вместе, копии базы нет. Если управляющий сервер лежит, кабинет и откат
     кнопкой недоступны; дежурный откатывает переключением `current` по ssh на
     Local Ru, это войдёт в `Инструкция_дежурного_v1.md`.
   - **На Local Ru с базой там же**: стык — только при недельной записи
     конвейера в базу через туннель. Пересчёт, сборка, «Выпустить сейчас» и откат
     обходятся без модели и без выхода в сеть, поэтому могут идти целиком на
     Local Ru. Минусы: там свободно около 1,9 ГБ памяти и нет браузера для
     проверки доступности, а база атласа встаёт рядом с KX.
4. **Разрешения, которые понадобятся на этапе 3:**
   - запись DNS `atlas.agpm.space` (сейчас её нет);
   - блок сайта в Caddy на Local Ru;
   - пользователь выкладки на Local Ru;
   - задача OpenClaw cron на понедельник 09:00 МСК;
   - служба кабинета.
   Новые юниты systemd и правки Caddy по правилам проекта делаются только с
   согласия владельца.
5. **Редакторы, почта для оповещений, предел расходов на прогон** (в токенах или
   обращениях).

Остальные открытые вопросы задания (асимметрия правила сигнала, перенос
сценариев автоматикой, «стартовый корпус», пороги качества, ссылки из радара и
газеты) нужны к приёмке своих этапов и сейчас ничего не блокируют.

1. **Основа атласа — данные радара V2.** Атлас берёт материалы только из API V2.

   Для сверки атлас сначала берёт текст статьи из кэша, который радар ведёт на
