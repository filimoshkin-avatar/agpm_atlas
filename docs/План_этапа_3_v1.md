```
──────────────────────────                     ─────────────────────────────────
OpenClaw cron, пн 09:00 МСК                    PostgreSQL 17: база atlas, роль atlas

  └ по ssh: «собрать и опубликовать» ────────► atlas publish: пересчёт, сборка, проверки,

                                               /srv/atlas.agpm.space/current → releases/…

                                               Caddy: atlas.agpm.space → current, /v/*, /editor/*
```

## Что меняется на Local Ru

Каждый пункт — изменение прода, делается только с согласия заказчика.

1. **PostgreSQL.** Новая база `atlas` и роль `atlas` с паролем. `pg_hba.conf`
   не меняется: вход по паролю с 127.0.0.1 уже разрешён. Базы KX, tea, nrd не
   затрагиваются.
2. **Перенос базы** с управляющего сервера (`pg_dump` → `pg_restore`, несколько
   мегабайт). Копия на управляющем сервере остаётся как резервная.
3. **Системный пользователь `atlas`** и `/opt/atlas`: код и окружение Python
   (psycopg, jinja2, argon2). Код приезжает выкладкой с управляющего сервера,
   доступ Local Ru к GitHub не нужен.
4. **Пользователь туннеля `atlas-tunnel`** с ключом, которому разрешено только
   перенаправление на 127.0.0.1:5432, без оболочки.
5. **Папка сайта** `/srv/atlas.agpm.space/` с версиями и указателем `current`.
   Собранные папки хранятся 90 дней — это около 12 МБ на версию.
6. **Служба `atlas-editor.service`** — кабинет на 127.0.0.1, ограничение
   памяти 200 МБ.
7. **Блок `atlas.agpm.space` в Caddy:**
   - корень — `current`, `/v/<дата>/` — из `releases`, `/editor/` — на кабинет;
   - ассеты с хэшем в имени отдаются immutable, страницы — no-store;
   - кабинет и снимки закрыты от индексации.
   Текст блока показываю до применения. Перед правкой — копия Caddyfile, после
   неё — `caddy validate`.

## Что меняется в другом месте

8. **DNS:** запись A `atlas.agpm.space → 194.87.143.141`. Её заводит заказчик у
   регистратора; HTTPS-сертификат Caddy получит сам.
9. **Расписание:** задача OpenClaw cron на управляющем сервере, понедельник,
   09:00 МСК, в профиле projectmanager. Новый юнит systemd не нужен.
10. **Оповещения:** сводка после публикации и тревога при сбое уходят в
    Telegram через `openclaw message send`. Кому их слать — вопрос к заказчику.

## Что пишу в коде

- `atlas publish`: пересчёт, сборка папки версии, блокирующие проверки
  (целостность, номера, потери, цифры, правило сигнала 26 из 26, резкие
  изменения, сайт), атомарное переключение `current`, журнал;
- `atlas rollback <версия>` — откат за минуту, с причиной;
- `atlas week` — повторы каждый час до 18:00, если выгрузка недоступна, и
  тревога; без новых материалов версия не создаётся;
- **минимальный кабинет:** вход (argon2, защита от перебора, сеанс 12 часов),
  лента изменений, очередь, кнопка «Опубликовать» для задержанной версии,
  откат;
- `Инструкция_дежурного_v1.md`.

## Порядок

1. Код и конфиги готовлю и проверяю на управляющем сервере. Прод на этом шаге
   не меняется.
2. Показываю блок Caddy, юнит и команды.
3. После согласия применяю пункты 1–7 на Local Ru и проверяю сайт и кабинет
   по адресу Local Ru.
4. Сайт открывается на atlas.agpm.space, когда появится DNS.
5. Публикуется версия 2026-10-27-2, включается расписание. Первый плановый
   прогон заберёт неделю 28.10–03.11.

подряд без вмешательства.
